# plan/019-rolling-week: 週の画面を、今日から7日に

- 元: プロダクトオーナーの要望(「週のところは、今日を起点に向こう7日くらいを表示するのはどうかな?」)。spec の変更 10(下記)
- 状態: 承認済み(承認者: リポジトリオーナー、2026-11-26)
- 進め方: plan/013(動き)より先に出す

## Context
週の画面は、月曜から日曜の暦の週を見せている(`WeekView.tsx` の `weekStartOf`、「今週 / 来週」)。週の後半になるほど過ぎた日が多くなり、これからの予定が見えにくい。今日から7日を見せれば、いつ開いても「これから」が同じ広さで見える。

## spec の変更 10(この plan の承認で受理とする)
- R8(改): 週の画面は、今日を起点に7日を見せる。「その先の7日」にも切り替えられる。予定の置き場所(ブロック)と、置いたものの保存の仕方(暦の週と曜日)は変えない。
- 省みる画面は、これまでどおり暦の週(月曜〜日曜)で省みる(週のメモや「この週の言葉」が週ごとに残っているため)。

## 変更
### 考え方
置いたものは、データベースでは「暦の週の月曜(`week_start`)」と「曜日(`day`、0 = 月曜)」で保存している。この形は変えず、画面だけを日付で並べる。今日から7日は、暦の週を最大2つまたぐので、2つの週の分を読んで、日付で並べ直す。

### ドメイン(`src/domain/week-grid.ts`、テスト付き)
- `daysGrid(start, now, timeZone, blocks)`(新規): `start` の日から7日分の格子。各セルに日付(`date`)、その日が属する暦の週(`weekStart`)、曜日(`weekday`、0 = 月曜)を持たせる。今の `weekGrid(weekStart, …)` は、`daysGrid` を月曜から呼ぶ形にして、省みる画面の動きは変えない。
- `cellKey` と `slackRatio` は日付で数える(`date/blockId`)。
- 2つの週をまたぐときの境目(日曜 → 月曜)、月末と年末、今日の過去・今・未来の判定をテストする。

### データ(`src/data/items.ts`)
- `listPlacementsFrom(start)`(新規): 7日がかかる暦の週(1つか2つ)の置いたものを読み、`date`(= `week_start` + `day`)を付けて返す。7日の外は除く。
- 置くときは、セルが持つ `weekStart` と `weekday` をそのまま使う(`placeNow` は変えない)。

### 画面(`src/ui/WeekView.tsx`)
- 見出しを「これからの7日」と「その先の7日」に。切り替えは今の「今週 / 来週」と同じ位置と形。
- 置いたもの、締め切り、カレンダーの予定は、日付で各日に並べる。カレンダーは `placeEvents` に7日の初日を渡す(初日からの日数で並べる関数なので、そのまま使える)。
- 曜日の表示は、セルの `weekday` から出す。
- 余白の割合は、見えている7日で数える。

## やらない
省みる画面の範囲を変えること。7日の幅を設定で変えること。

## リスク
- **置いた日がずれる**: 暦の週をまたぐ計算を誤ると、別の日に表示される。境目のテストで防ぐ。保存の形は変えないので、すでに置いたものは影響を受けない。
- **読み込みが2回になる**: 2つの週を1回の問い合わせ(`week_start` の `in`)で読む。

## 証明(Proof)
- `npm run lint`、`npm test`、`npm run build` が通る。CI と AI レビュー(Important 0 件)を通る。
- あなたの確認(マージ後): 週の画面の先頭が今日になっていて、7日先まで並ぶ。日曜をまたいだ先の日にも、置いたものや予定が正しい日に出る。「その先の7日」に切り替えられる。

## 計画からのずれ
- セルの `day` は「格子の中での位置(初日から何日目か)」のまま残し、曜日は新しい `weekday` に分けた。省みる画面(`weekGrid` を月曜から呼ぶ)では、両方が同じ値になるので、省みる画面とその集計(`review.ts`)は変えずに済んだ。
- 今日の日付を出す `todayOf` を `week-grid.ts` に足した(設定のタイムゾーンで数える)。
