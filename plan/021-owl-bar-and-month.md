# plan/021-owl-bar-and-month: ふくろうは上のバーに、いつも見える。月のカレンダー

- 元: プロダクトオーナーの要望(「下へスクロールしても、上のバーとふくろうは残るように」「各ページに行っても、ふくろうは残してほしい」「カレンダーの月の表示を追加したい」)。ふくろうは「上のバーの中」、月に出すものは「Google カレンダーの予定、締め切り、置いた予定、終えたこと」のすべてを選んだ。spec の変更 12(下記)
- 状態: 承認済み(承認者: リポジトリオーナー、2026-11-26)
- あわせて、PR #18 のレビューで残した Nit 4件も直す

## Context
- 上の帯(日付とタブ)は、下へ送ると隠れる作りにした(plan/020)。プロダクトオーナーは、いつも見えているほうを望んだ。
- ふくろうは「今」の画面だけにいて、時間帯と日付で居場所が変わる(R36)。週や省みるの画面では見えない、スクロールすると見えなくなる。
- 予定を1か月の広さで見渡す画面がない。

## spec の変更 12(この plan の承認で受理とする)
- R36(改): ふくろうは上のバーの中にいて、どのページでも、スクロールしても見える。姿(見守る、本を読む、眠る)は時間帯で変わる。居場所が変わる仕組みはやめる。押すと跳ねて一言、終えたら跳ねる、話して省みる間の様子、目で追う動きはそのまま。
- R43(補の改): 日付とタブのバーは、スクロールしてもいつも上に残る(下へ送るときに隠す動きはやめる)。
- R48(新): 月のカレンダーを見られる(タブ「月」)。月曜始まりの格子に、Google カレンダーの予定、締め切り(〆)、置いた予定、終えたことを、日ごとに出す。過ぎた日は薄く、今日は強調する。前の月・次の月に移れる。日を押すと、その日の中身を格子の下に一覧で出す。目標値や達成率、評価の色は出さない(R16)。

## 変更
### ふくろうを上のバーに
- `App.tsx`: 帯の中、日付とタブのあいだにふくろうを1羽だけ置く(少し小さく、`Owl` に `size` を足す)。どのタブでも同じふくろう。
  - 姿は `owlFor` の `pose`(時間帯と、今のブロックに置いたものがあるか)。`spot` は使わなくなるので、`owl.ts` から外し、テストも直す。
  - 「今」の画面の `NowView`、`App` の2か所、`ReviewView` にいたふくろうを外す。
  - 話して省みるの様子(`mood`)は、`ReviewView` から `App` に上げて、バーのふくろうに渡す。終えたときに跳ねる `nudge` もそのまま渡す。
- 帯は隠さない: `useScroll` から `headerHidden` を外す(`domain/scroll.ts` の `headerHidden` とテストも外す)。少しでもスクロールしたら下に線を引くのは残す。
- スキルの「ふくろう」の節を改める(居場所が変わる → バーにいて姿が変わる)。

### 月のカレンダー
- タブを「今 / 週 / 月 / 省みる」にする。
- `src/domain/month-grid.ts`(新規、テスト付き): `monthGrid(year, month, today)` → 月曜始まりの週の行(前後の月の日も含めて埋める)。各日に、日付、その月の日かどうか、過去・今日・未来。月の範囲(`monthRange`)、前後の月への移動。
- `src/data/items.ts`:
  - `listPlacementsBetween(start, end)`: 範囲がかかる暦の週(`weeksCovering` を範囲に広げた `weeksBetween`)の置いたものを読み、日付で絞る。`listPlacementsFrom` もこれを使う形にまとめる。
  - `listCompletedBetween` に、終えた日(`updated_at` の日付、設定のタイムゾーン)を付けて返す形を足す。
  - 締め切りは今の `listDue({ from, to })`、カレンダーは今の `fetchEvents(start, end)` をそのまま使う。
- `src/ui/MonthView.tsx`(新規):
  - 見出しは「11月」。「前の月 / 今月 / 次の月」。
  - 格子は7列。PC では、各日に数件まで短く書く(予定、〆、置いた予定。終えたことは薄く「終えた N」)。多い日は「ほか N」。
  - スマホでは、各日は日付と小さな印(墨の点)だけにして、押すと下に一覧を出す。
  - 日を押すと、格子の下に、その日の中身を箇条書きで出す(`ListMark`)。
  - 見えてきたら現れる動き(`Reveal`)はほかの画面と同じ。
- 引用(`QuoteLine`)は月の画面にも1つ(`screen` に `month` を足し、束のずらしを4つにする。30日重ならないことと、同じ時刻の画面どうしで重ならないことのテストを直す)。

### PR #18 のレビューの Nit

- 「終えた。」を書き込む動きは、保存できてから始める。
- plan/020 の「計画からのずれ」に、瞳の動きの幅(最大 1.5px)と、空の計算を止めない点を書き足す。

## やらない
月の画面から予定を置くこと(置くのは週の画面で)。年の表示。

## リスク
- **月の画面の読み込みが重い**: 予定、締め切り、置いた予定、終えたことを、月ごとに1回ずつ読む(4つの問い合わせを同時に)。月を切り替えたときだけ読み直す。
- **スマホで格子が細い**: 7列で1列 45px ほどなので、文字は出さず、日付と印だけにする。
- **ふくろうがバーを窮屈にする**: 少し小さくして、日付とタブのあいだに置く。スマホでは日付を短く(「26日(木)」)。

## 証明(Proof)
- `npm run lint`、`npm test`(`month-grid.ts`、`weeksBetween`、引用の4画面、`owlFor` の変更を含む)、`npm run build` が通る。CI と AI レビュー(Important 0 件)を通る。
- ダミーのデータを返す形で開き、PC とスマホの幅で、月の画面と、スクロールしてもバーとふくろうが残ることを Playwright の画像で確かめる。

## 計画からのずれ
- `placeEvents` に日数(`days`、既定は7)を足し、月のカレンダーでは格子の日数(35〜42日)を渡すようにした。週の画面の動きは変わらない。
- 日ごとのまとめ方(予定、締め切り、置いた予定、終えたこと)を `month-grid.ts` の `collectByDate` にして、テストを付けた。置いた予定で終えたものは、終えたことに重ねて数えない。
- PC の格子では、終えたことは行に書かず、「終えた N」と数だけ薄く出す(置いた予定で終えたものも含めて数える)。
- 省みる画面で、話して省みる間は、バーのふくろうが起きた姿になって様子を見せる(本を読む姿のままでは目が見えないため)。
- スマホのバーでは、日付から「11月」を外して「26日(木)」にした。
- 見え方は、ダミーのデータを返す形で開いた画面を Playwright で撮って確かめた(PC とスマホの幅で、スクロールしたあとの「今」と「月」)。
