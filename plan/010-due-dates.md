# plan/010-due-dates: Google ToDo の日付を「今」と「週」に生かす

- 元: プロダクトオーナーのフィードバック(2026-11-23)。spec の変更 4(下記)。PR #3、#4 のレビューの Nit 7件
- 状態: 承認済み(承認者: リポジトリオーナー、2026-11-23)

## Context
Google ToDo では、タスクの日付を締め切りとして使っている。その運用をアプリでも生かし、今日が締め切りのものは「今」の画面に自動で出したい。
あわせて、使ってみて気になった点が2つあった: Inbox の名前「ふと浮かんだこと」は、Google ToDo の課題も入るので合わない。週の画面の「描く」は言葉として変で、毎日に出ていて邪魔。

## spec の変更 4(この plan の承認で受理とする)
- R38(新規): 締め切り(Google ToDo の日付)が今日のもの、または過ぎていてまだ終えていないものは、「今」の画面に「今日までのこと」として自動で出る。過ぎたものには日付を添えるだけで、警告の色や口調にはしない(R16、R23)。その場で終えた印を付けられる。
- R39(新規): 週の画面では、締め切りのあるものを、その日に薄く出す。
- R7(具体化): 締め切りは Google ToDo の日付と同期する(plan/005 で実装済み)。やることの一覧にも日付を添える。
- 名前の変更: Inbox の画面上の名前を「やること」にする。入力欄の「ふと浮かんだことを」はそのまま。

## 変更
### 今日までのこと(R38)
- 中身の計算 `src/domain/due.ts`(テスト必須): 項目と今日の日付から、「今日まで」(今日が締め切り)と「過ぎたもの」に分け、締め切りの早い順に並べる。完了したもの、削除したもの、「いつか/やらない」は除く。
- データ: `src/data/items.ts` の項目に締め切り(`due_date`)を含める。締め切りが今日以前の未完了の項目を読む関数を足す。項目を直接「終えた」にする関数を足す(ブロックに置いていなくても終えられるように)。同期で Google ToDo にも完了が届く。
- 画面: 「今」の左の列、今やることの下に「今日までのこと」。手描きの丸(小さめ)で終えられる。過ぎたものには「11/28 まで」のように日付を添える。何もなければ出さない。

### 週の締め切り(R39)
- 週の画面で、その週に締め切りのある未完了の項目を、日ごとに「〆 組織行動論レポート」のように薄墨で出す。

### やること(名前の変更)
- `InboxList` の見出しを「やること」に。一覧の各項目に、締め切りがあれば日付を添える(締め切りの早い順、締め切りなしは後ろ)。
- スキル `life-dashboard-look` の「使う言葉」を更新する。

### 週の「描く」をやめる
- 日ごとの「描く」の言葉をなくし、日付の横に、さりげない「+」を置く(押せる範囲は 44px を保つ)。押すと、今までと同じく、ブロック名 → 候補の順に選ぶ。

### PR #3、#4 のレビューの Nit(7件)
- 今の画面で、項目ごとに `h1` が並ぶ → 画面の見出しを1つにし、項目は `h2`。
- 引用のテストが、言葉の並びが変わると壊れる → 複数の日で2種類以上選ばれることを確かめる形に。
- 外部の書体(Google Fonts)への依存を plan/008 のリスクに追記。
- `useAutoSync` で、例外が起きても次の同期が止まらないようにする(`finally`)。
- 試作の鍵(`spike-002`)を、アプリを開いたときにも消す。
- `google-tasks` の冒頭のコメントを、今の振る舞いに合わせる。
- plan/009 に残った下書きの一文を消す。

## やらない
締め切りの通知(R22。サーバー側の定期実行と一緒に)。締め切りの時刻(Google ToDo の日付は日単位のため、扱わない)。

## リスク
- **締め切りの日付のずれ**: Google ToDo の日付は UTC の0時で届く。日付の部分だけを使い、タイムゾーンで前日や翌日にずれないようにする(plan/005 の同期ですでにこの扱い)。テストで押さえる。
- **「今」の画面が締め切りで埋まる(P1、P7)**: 今日までのことは、今やることより小さく、下に置く。主役は今やること。
- **ブロックに置かずに終えた項目**: 振り返りの集計(R15)は「ブロックで使った時間」なので、ブロックに置かずに終えたものは時間には数えない。振り返りの plan で扱いを決める。
