# plan/022-pillars-matrix-detail: 人生の柱、四つに分ける、やることの詳細

- 元: プロダクトオーナーとの相談(「タスクをクリックしたとき、そのタスクを進めることにつながるといい」「Claude に相談で claude.ai に飛ぶ」「健康みたいな重要度を取り込みたい」「領域は見直したい」「重要度と緊急度のマトリックスをどこかに」)。領域は「人生の柱」(2つ目の案)、マトリックスは「やることの切り替え」、詳細は「メモ、最初の一歩、今やる・終えた・手放す」+「Claude に相談」を選んだ。spec の変更 13(下記)
- 状態: 承認済み(承認者: リポジトリオーナー、2026-11-26)
- PR は3本に分ける: A(人生の柱)→ B(四つに分ける)→ C(やることの詳細)。あわせて PR #19 のレビューの Nit 3件を A で直す

## Context
- 領域は用事の種類(仕事、スキル強化、学校、プライベート、新規ビジネス)で、5つに固定されている。使い道は省みるの「時間の使い方」だけ。「健康」のように、人生で大事にしたいものを物差しにできない。
- 4象限のマトリックス(spec R5)は、まだ画面にない。
- やることを押すと、仕分けの欄が開くだけで、その仕事を前に進める手がかりがない。

## spec の変更 13(この plan の承認で受理とする)
- R4(改): 各項目に「人生の柱」を1つ付けられる。柱は本人が決める(名前の追加、名前の変更、削除、並べ替え)。最初は「健康、仕事、学び、人とのつながり、新規事業、暮らし」の6つ。AI の見立ても、本人の柱から選ぶ。
- R15(補): 省みるの「時間の使い方」は、柱ごとに、その週に何度、どれくらい時間を向けたかを文章で見せる(「健康には、2回、時間を向けた」)。目標値、達成率、評価の色は出さない(R16)。
- R5(改): やることを「一覧 / 四つに分ける」で切り替えられる。四つに分けたときは、大切で急ぐ、大切で急がない、急ぐだけ、どちらでもない、に並べる。まだ分けていないものは、下にまとめる。項目を押して、別の局面へ移せる。
- R49(新): やることを押すと、その仕事を進めるための詳細が開く。メモ(Google ToDo の「詳細」と同期)、最初の一歩(一行)、今やる・終えた・いつかに手放す、Claude に相談。仕分け(柱と、大切/急ぐ)は、見立てを一行で薄く示し、「直す」を押したときだけ選ぶ欄が開く。
- R50(新): 「Claude に相談」は、項目の題名、締め切り、メモ、最初の一歩を入れた相談の文を作り、claude.ai の新しいチャットを新しいタブで開く。アプリから Claude に自動で送るものはない(送るかは本人が開いた画面で決める)。
- C16: 相談の文には、やることの中身が入る。claude.ai に送るかは本人が決める。

## A: 人生の柱(先に出す)
### データ
- マイグレーション:
  - `settings` に `pillars jsonb`(`[{ id, label }]`、既定は6つ)を足す。
  - `items.area` と `task_list_links.area` の固定の値の制約(check)を外し、柱の id を入れられるようにする。
  - 今ある値を移す: work → 仕事、skill と school → 学び、private → 暮らし、business → 新規事業(id はそれぞれ `work`、`learning`、`life`、`venture`)。健康(`health`)と人とのつながり(`people`)は新しく足す。移したものは `area_source` をそのままにする。
  - 列の追加と制約の変更なので、RLS と権限は変わらない。pgTAP で、既定の柱、移した値、制約がないことを確かめる。`npm run gen:types`。
- `src/data/settings.ts`: `AppSettings` に `pillars` を足し、読み書きする。
- `src/domain/areas.ts` → `src/domain/pillars.ts`: 既定の柱、id の作り方(名前から決めず、`p-` と短い乱数)、名前の重なりや空の検査。テスト付き。
### AI の見立て
- `_shared/classify.ts`: 固定の `CLASSIFY_AREAS` をやめ、本人の柱(id と名前)を指示と返す形(`enum`)に入れる。応答の検査も、本人の柱の id で行う。
- `classify` 関数: `settings.pillars` を読んで渡す。
- 評価: `evals/classify/cases.json` の期待値を新しい柱にし、柱の一覧も例に持たせる。Evals(classify)が回る PR なので、○×の表を確かめてからマージする。
### 画面
- 柱を直す場所: 画面の下(ログアウトの上)に「人生の柱」を置き、名前を直す、足す、消す、並べ替える。消した柱が付いていた項目は、柱なしに戻る(AI はもう一度見立てない)。
- 省みる: 「時間の使い方」を柱ごとの文章にする(`review.ts` の `timeSpent` を柱で数える)。
- やることの一覧、詳細、月の画面の柱の表示を、本人の柱の名前で出す。
### PR #19 のレビューの Nit
- 月の画面で読めなかったとき、「余白の一日」ではなく「読めなかった」と一言出す。例外で「開いています…」のままにならないようにする。
- 終えたことの二重の表示を、項目の id で突き合わせて防ぐ。
- 日を押した一覧の見出しを「今日までのこと」から「〆」にする。

## B: 四つに分ける
- `src/domain/quadrant.ts` に、項目を4つの局面と「まだ分けていない」に分ける関数(テスト付き)。
- `InboxList.tsx`: 見出しの横に「一覧 / 四つに分ける」。選んだほうはその端末で覚える。
- 四つに分けたとき: PC は2×2の格子、スマホは4つを縦に並べる。各局面に箇条書き。項目を押すと詳細(C)が開き、そこで局面を移せる。見立ての局面は薄く示す(今の点線と同じ)。
- 局面の名前は「大切で急ぐ」「大切で急がない」「急ぐだけ」「どちらでもない」。「大切で急がない」を左上ではなく強調せずに並べる(順位や評価の色は付けない)。

## C: やることの詳細
### データ
- マイグレーション: `items` に `notes text`(Google ToDo の「詳細」)と `first_step text`(最初の一歩、80字まで)を足す。`updated_at` のトリガーは、`notes` の変更でも進める(Google ToDo に送るため)。`first_step` は送らないので進めない。pgTAP で確かめる。
- 同期(`_shared/sync.ts`、`google-tasks`): Google ToDo の `notes` を読み書きする。どちらが新しいかの判定は、今の題名と同じ仕組みに乗せる。`planSync` のテストに、メモの行き来を足す。
### 画面
- `ItemDetail.tsx`(新規、今の `ItemMeta` を置き換え): 押すと開く。
  - 締め切り、柱、大切/急ぐの見立てを一行で(「学び・大切で急がない(見立て)」)。「直す」で今の選ぶ欄が開く。
  - メモ: 下線だけの欄。離れたときに残し、次の同期で Google ToDo に届く。
  - 最初の一歩: 一行。「まず、〜する」。
  - 操作: 今やる(今のブロックがあるとき)、終えた、いつかに手放す。
  - 「Claude に相談」: `src/domain/consult.ts`(テスト付き)で相談の文を作り、`https://claude.ai/new?q=…` を新しいタブで開く。文は「〇〇(締め切り 11/28)に取りかかりたい。メモ: … まずは … から始めたい。どう進めるか一緒に考えてほしい。」の形。長すぎるときはメモを切る。
- 「今」の画面のやること、今日までのこと、月の画面の日の一覧から、同じ詳細が開く。

## やらない
最初の一歩を AI が提案すること(相談は Claude で)。柱ごとの目標や、柱の色分け。Google ToDo のリストと柱の自動の結びつき。

## リスク
- **柱の移し替え**: 学校とスキル強化を「学び」にまとめるので、元に戻せない。プロダクトオーナーには、移し替えの対応を PR に書いて確かめてもらう。
- **AI の見立てが本人の柱に合わない**: 柱の名前だけでは意味が伝わりにくい。評価の例に、柱の一覧つきの例を持たせ、一致率を見る。
- **メモの同期で上書きが起きる**: 題名と同じ「新しいほうが勝つ」の仕組みに乗せ、`planSync` のテストで両方向を確かめる。
- **claude.ai の URL**: `?q=` で入力欄に文が入る形を使う。claude.ai の仕様が変わって文が入らなくても、新しいチャットは開く。マージ後にプロダクトオーナーに確かめてもらう。

## 計画からのずれ
### A(人生の柱)
- 柱は、画面のどこからでも引けるよう React の Context(`pillars-context.ts`)で配る。
- 関数(Deno)はリポジトリの `src` を読めないので、最初の6つを `_shared/classify.ts` にも置き(`DEFAULT_CLASSIFY_PILLARS`)、`src/domain/pillars.ts` と同じであることをテストで確かめた。保存された柱の形が違うときも、最初の6つで見立てる。
- 柱を消したとき、その柱が付いていた項目は柱なしに戻し、`area_source` を本人(`user`)にする(AI がもう一度見立てて、消した柱の代わりを勝手に付けないように)。
- 省みるの柱の一文は「健康には、2回、およそ1時間、時間を向けた。」の形にした。
- 箇条書きの印(`ListMark`)に、行の高さに合わせて位置を変える `className` を足した(柱の編集の行は上下の余白がないため)。
- 見え方は、ダミーのデータを返す形で開いた画面を Playwright で撮って確かめた(やることに柱の名前が出る、詳細で柱を選べる、画面の下で柱を直せる)。
- PR #20 で Evals(classify)が、Gemini の時間切れ(25 秒)で「評価できなかった」になった。原因は2つ: 15件をまとめて送る見立ては、柱の一覧が加わって返事に時間がかかるようになった。また、時間切れは「待てば通りうる失敗」として扱っておらず、呼び直しも控えのモデルへの切り替えもしていなかった。`_shared/ai.ts` に1回の待ち時間の上限(`timeoutMs`)を足し、時間切れと通信の途切れも呼び直しと切り替えの対象にした。見立ての関数は 45 秒・呼び直しなし・控え1回(最悪でも約 90 秒)、評価は 90 秒にした。窓口(`ai.ts`)を変えたので、話して省みるの評価も回る。
