# plan/015-small-fixes: 見出しの改行、毎回のログイン、やることの見やすさ

- 元: プロダクトオーナーの指摘(ログイン画面の見出しが「手 / 帳。」で折り返す、毎回ログインと Google の許可を聞かれる、タスクの視認性が低い、トップのやることは最初から開いていて押すと閉じられるほうがよい)。spec の変更 8(下記)
- 状態: 承認済み(承認者: リポジトリオーナー、2026-11-26)
- 進め方: PR #10(plan/014)のマージ後、同じ作業ブランチで。plan/013(動き)より先に出す(小さく、毎日の使いにくさに効くため)

## Context
ふだん使う中で、小さな使いにくさが4つ見つかった。
1. 見出しが語の途中で折り返す(「小さな手 / 帳。」)。
2. 開くたびに、ログイン画面に戻り、Google の許可画面も毎回出る。
   - 許可画面の原因はコードにある。ログインのたびに `prompt: 'consent'`(毎回許可を求める指定)を付けている(`src/data/supabase.ts`)。Google の長期の鍵を受け取るためだったが、鍵はサーバーに保管済みなので、毎回は要らない。
   - ログインが外れる原因は、コードからは見つからない(セッションはブラウザに保存される既定の設定)。Supabase の認証のログを見て確かめる(下の「あなたにお願いすること」)。
3. やることの文字が薄く小さい(本文が `ink-2` の 15px、見出しが `ink-3` の 12px)。
4. トップのやることが、ふだん閉じている(R13 で「折りたたむ」と決めていた)。

## spec の変更 8(この plan の承認で受理とする)
- R13(改): 「今」の画面のやることは、最初から開いて表示する。見出しを押すと閉じられ、閉じたかどうかはその端末で覚えておく。全体のリストが「こなすべき全て」に見えないよう、件数が多いときは最初の数件だけ見せる(P1)。
- R45(新): Google の許可画面は、初めてつなぐときと、つながりが切れたときだけ出す。

## 変更
### 1. 見出しの改行
- `src/index.css`: 見出し(`h1`、`h2`)に `word-break: auto-phrase`(日本語を文節で折り返す)と `text-wrap: balance`(行の長さをそろえる)。使えないブラウザでは、今と同じ折り返しになるだけ。
- `src/ui/SignIn.tsx`: 「今を選ぶための、」の後で改行する(`<br />`)。どの幅でも「今を選ぶための、 / 小さな手帳。」になる。

### 2. 毎回の許可画面とログイン
- `src/data/supabase.ts`: `signInWithGoogle({ consent })` にする。ふだんは `prompt: 'consent'` を付けない(`access_type: 'offline'` は残す)。
- つながりが切れたとき(同期やカレンダーが `409 reconnect` を返したとき)だけ、許可を求めてつなぎ直す。
  - `src/data/sync.ts` の `RECONNECT` の文言を「Google とのつながりが切れている。つなぎ直すと戻る。」に変える。
  - `App.tsx` の知らせの横に「つなぎ直す」を置き、`signInWithGoogle({ consent: true })` を呼ぶ(ログアウトは要らない)。
- 初めてのログインでは、サーバーに鍵がまだないので、同期が `409` を返す。そのときも同じ「つなぎ直す」で許可を求める。初回の流れは「Google で開く → つなぎ直す」の2回になるが、2回目以降は許可画面が出ない。
- ログインが外れる件: ログを見てから直す。原因がわかったら、この plan の「計画からのずれ」に書き、同じ PR で直す。

### 3. やることの見やすさ
- `InboxList.tsx`、`TodayDue.tsx`: 本文を `ink`(墨)の 16px にする。日付などの添え書きは `ink-3` のまま。見出し(「やること」「今日までのこと」)は `ink-2` の 13px にする。
- 週の画面は、今回は変えない(見やすさの指摘はトップの話だったため。使ってみてから)。

### 4. やることを最初から開く
- `InboxList.tsx`: 最初から開いた状態にし、開閉を `localStorage` で覚える(読めない環境では開いたまま。`try/catch` で包む)。
- 件数が多いときは、最初の 7 件だけ見せ、「ほかに N 件」を押すと残りを出す(P1: 一覧が「こなすべき全て」に見えないように)。並び順は今の `sortForList` のまま。

## テスト
- 単体テスト: 最初の数件と「ほかに N 件」の数を決める純粋な関数(`src/domain/list-preview.ts`)。
- 画面は、あなたの目で確かめる。

## あなたにお願いすること(ログインが外れる件)
- Supabase のダッシュボードで、Authentication の Logs(または Logs & Analytics の Auth)を開き、ログインが外れた日のエラーを見る。`refresh_token_not_found` や `Invalid Refresh Token` があれば、その行の内容を教えてほしい(鍵や個人の情報は貼らない)。
- あわせて、どの端末とブラウザで外れるかを教えてほしい(例: iPhone の Safari だけ、PC の Chrome でも、など)。iPhone の Safari は、しばらく開かないサイトの保存内容を消すことがある。

## やらない
週の画面の見やすさ。ホーム画面に追加して使う形(PWA。ログインが外れにくくなるので、ログの結果しだいで次に検討する)。

## リスク
- 許可画面を出さないと、Google が長期の鍵を渡さないことがある。鍵はサーバーに保管済みなので困らない。鍵がなくなったときは `409` で「つなぎ直す」が出る。
- `word-break: auto-phrase` は新しめの指定で、使えるのは Chrome などに限られる。ログイン画面は `<br />` で確実に直す。

## 証明(Proof)
- `npm run lint`、`npm test`、`npm run build` が通る。CI と AI レビュー(Important 0 件)を通る。
- あなたの確認(マージ後):
  - ログイン画面の見出しが「今を選ぶための、 / 小さな手帳。」で折り返す。
  - ログアウトしてもう一度「Google で開く」を押しても、Google の許可画面が出ない(アカウントの選択だけ)。
  - トップのやることが最初から開いていて、見出しを押すと閉じ、開き直しても閉じたままになる。文字が前より読みやすい。

- 「つなぎ直す」は、画面の下にある同期の知らせの横に置いた(知らせがすでにそこにあるため)。
