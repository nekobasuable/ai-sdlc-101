# plan/020-scroll-and-list: やることの幅と箇条書き、スクロールしたときの動き

- 元: プロダクトオーナーの指摘(「やることの幅が少し狭い」「箇条書きっぽいほうが見やすい」「スクロールした感じが、いかにも静的なページ」)。幅は「右の列を広げる」、スクロールの動きは4つすべてを選んだ。spec の変更 11(下記)
- 状態: 承認済み(承認者: リポジトリオーナー、2026-11-26)
- あわせて、PR #16 と PR #17 のレビューで残した Nit 4件も直す

## Context
- PC の「今」の画面は左右 7:4 の2列で、右の列のやることは 340px ほどしかない。長い題名が何行にも折り返す。
- やることは、行と行の区切りがなく、どこからどこまでが1件かが見えにくい。
- 動きは操作と時間の移り変わりにだけ付けたので、スクロールしても紙が平らに動くだけに見える。

## spec の変更 11(この plan の承認で受理とする)
- R37(補): PC の2列は 3:2 にする。
- R47(新): やることや締め切りの一覧は、1件ずつの頭に小さな墨の印を付けた箇条書きにする(手帳の行のように)。
- R43(補): スクロールにも、手帳らしい応え方をする。見えてきたまとまりは墨がにじむように現れ(一度だけ)、上の空は少し遅れて動き(奥行き)、日付とタブは上に残る(下へ送るときは控えめに隠れ、戻すと現れる)、ふくろうは目でスクロールを追う。動きを減らす設定では、どれも動かさない(日付とタブは上に残るだけ)。

## 変更
### やることの幅と箇条書き
- `App.tsx`: PC の格子を `lg:grid-cols-[7fr_4fr]` → `lg:grid-cols-[3fr_2fr]`、間も `lg:gap-24` → `lg:gap-16`。
- `InboxList.tsx`、`TodayDue.tsx`(今日までのこと)、`ItemMeta` はそのまま。各行の頭に、手で描いたような短い墨の印(`ListMark.tsx`、小さな SVG の点か短い線、`ink-3`)を付け、行のあいだに薄い罫線(`rule-soft`)を引く。今日までのことは、印の代わりに今の「終えた」の丸を使う(押せるため)。
- スキルの「部品の作り方」に箇条書きの決まりを書く。

### スクロールの動き(どれも `src/ui/useScroll.ts` の1つの仕組みから)
- **見えてきたら書き込まれる**: `Reveal.tsx`(新規)。`IntersectionObserver` で、画面に入ったまとまり(今日までのこと、今日のこれから、一日の一言、やること、引用、週の各日、省みるの各まとまり)に `ink-in` を一度だけ付ける。最初から見えているものは、そのまま見せる(開いた瞬間に全部がにじむとうるさいため)。
- **空が遅れて動く**: `Sky.tsx` に、スクロール量の 0.3 倍だけ下へずらす `transform`(`requestAnimationFrame` でまとめる)。空が見えなくなったら計算しない。
- **日付とタブが付いてくる**: `App.tsx` の見出しを `sticky top-0`、紙の色の帯(`bg-paper`、下に `rule-soft` の線)にする。下へ送ると上へ隠れ、上へ戻すと現れる(スクロールの向きで `translate`)。
- **ふくろうが目で追う**: `Owl.tsx` の瞳(起きている姿)を、スクロールの向きと速さに合わせて上下に 1px ほど動かし、止まると戻す。
- 純粋な計算(隠すか見せるかの判定、空のずらし量、瞳のずれ)は `src/domain/scroll.ts` に置いてテストする。
- 動きを減らす設定では、`useScroll` が値を返さない(空も瞳も動かず、日付とタブは隠れず上に残る、見えてきても現れる動きをしない)。

### PR #16、#17 のレビューの Nit
- 7日がかかる暦の週を求める部分を `week-grid.ts` の純粋な関数(`weeksCovering(start)`)にして、`items.ts` から使い、境目をテストする。`weekdayOf` を export して二重の計算をなくす。`todayOf` は年月日の整形だけにする。
- 眠っているふくろうは、押しても何も起きないので `button` にしない(キーボードで選べないように)。
- 「終えた」の墨のしぶきは、保存が終わってから散らす(`onResult` が成否を返すようにする)。
- 文字の飛び先が見つからないときも、「やることに入った。」と「週」の点は出す。

## やらない
スクロールに合わせて文字を動かし続けること(読みにくくなるため)。スマホの2列化。

## リスク
- **スクロールが重くなる**: スクロールのたびの計算は `requestAnimationFrame` で1回にまとめ、`transform` だけを変える(配置の計算をさせない)。
- **上に残る帯が場所を取る**: スマホでは帯を細くし、下へ送るときは隠す。
- **にじむ動きがうるさい**: 一度現れたら二度と動かさない。最初から見えているものには付けない。

## 証明(Proof)
- `npm run lint`、`npm test`(`scroll.ts`、`weeksCovering` を含む)、`npm run build` が通る。CI と AI レビュー(Important 0 件)を通る。
- ログイン画面と、ダミーの設定で開いた画面で、帯が上に残り、スクロールで隠れたり現れたりすることを Playwright で確かめる。
- あなたの確認(マージ後): PC でやることの幅が広くなり、1件ずつが箇条書きで見分けやすい。スクロールすると、まとまりがにじむように現れ、空が少し遅れて動き、日付とタブが付いてきて、ふくろうの目が動く。

## 計画からのずれ
- 空は遅れて動くだけでなく、下へ送るにつれて薄れるようにした(空が下の見出しに重なって読みにくくならないように)。
- 箇条書きの印は、点ではなく、手で引いたような短い墨の線にした。
- 日付とタブの帯の下の線は、少しでもスクロールしたときだけ引く(ページの上では線のない手帳のまま)。
- 見え方は、ダミーのデータを返す形で開いた画面を Playwright で撮って確かめた(PC の幅で、開いたとき、下へ送ったとき、上へ戻したとき)。帯が隠れて戻ること、空が遅れて薄れること、やることの列が広くなり罫線で区切られることを見た。箇条書きの印が文字より上にずれていたので直した。
