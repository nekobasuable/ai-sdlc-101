# plan/011-voice-reflection: 話して省みる(AI が下書きを整える)と、その評価(evals)

- 元: プロダクトオーナーの要望(2026-11-24)。spec の変更 5(下記)。プレイブック Stage 4「CI での継続的な評価(evals)」。PR #7 のレビューの Nit 3件
- 状態: 承認済み(承認者: リポジトリオーナー、2026-11-24)

## Context
振り返りを、音声入力で思ったことをそのまま話し、そこから整理する形にしたい。AI をバックエンドに入れたい。費用は Gemini API の無料枠で抑える。
AI の振る舞いは、コードのテストだけでは確かめられない。プレイブック Stage 4 に沿って、評価用の例(evals)を作り、AI への指示を変えるたびに CI で確かめる。

## spec の変更 5(この plan の承認で受理とする)
- R40: 省みる画面で、話した(書いた)文章から、AI が下書きを作る。下書きは「この週の言葉」「気づいたこと」「来週に持っていきたいこと」「手放してよさそうなこと」。何を残すかは本人が選ぶ。
- R41: AI の下書きは、次を守る: 評価や点数、励ましの言葉をつけない。話していないことを付け足さない。本人の言葉づかいを残す。命令形にしない(P3、R16、R23、C9)。
- R42: AI の呼び出しは、サーバー側の関数の1か所にまとめ、AI の提供元(Gemini、Claude)を差し替えられるようにする。最初は Gemini API の無料枠を使う。
- N7: AI への指示(プロンプト)や使うモデルを変えたときは、評価用の例で振る舞いを確かめる(CI)。
- C14: Gemini API の無料枠では、送った内容が提供元のサービス改善に使われることがある。プロダクトオーナーが受け入れたリスクとする(規約は本人が確認する)。
- R24(AI 仕分け)は、この仕組みの上で後の plan で作る。

## 変更
### 判断と形の部分(純粋な関数、テスト必須)
- `supabase/functions/_shared/reflect.ts`:
  - AI への指示(R41 を守らせる文)と、返してほしい形(JSON の型)を組み立てる関数。
  - AI の返事を受け取って形を確かめ、整える関数。形が違えば失敗として扱う。項目の数や長さに上限を付ける。
- `supabase/functions/_shared/ai.ts`: 提供元を差し替えられる窓口(`generateJson(prompt, schema)`)。まずは Gemini の実装だけ。API キーとモデル名は関数の Secrets から読む(`GEMINI_API_KEY`、`GEMINI_MODEL`)。

### サーバー側の関数 `reflect`(新規)
- ログインの証明で本人を確かめる。受け取る文章の長さに上限(4000文字)。
- AI を呼んで下書きを返す。保存はしない(残すかは本人が画面で選ぶ)。
- 失敗したら「いまは整えられなかった。話したことは、そのまま残せる。」と返す。

### 画面(省みる)
- 「話して省みる」の欄: 下線だけの複数行の欄(手書き風の書体)。スマホのキーボードのマイクで話せる。
- 「整える」を押すと下書きが出る。
  - この週の言葉、気づいたこと: その場で直せる。
  - 来週に持っていきたいこと: 1つずつ選べる(最初は選ばれていない)。
  - 手放してよさそうなこと: 読むだけ。
- 「残す」: この週の言葉と気づいたことを「この週のこと」に書き足し、選んだものを「やること」に入れる。
- AI を使わずに、話した文章をそのまま「この週のこと」に残すこともできる。

### 評価(evals、プレイブック Stage 4)
- `evals/reflect/*.json`: 評価用の例を10件ほど。話した文章(作った例。本人のデータは使わない)と、守るべきこと(例: 「来週に持っていきたいこと」に〇〇が入る)。
- `evals/run-reflect.ts`: 例ごとに `reflect.ts` の指示で Gemini を呼び、決まった検査をかける。
  - 共通の検査: 命令形の言い回し(「〜してください」「〜しましょう」)がない。評価や励ましの言葉(「素晴らしい」「頑張」など)がない。数字の点数がない。
  - 例ごとの検査: 拾うべきことが入っている。話していない固有名詞を足していない(例に書いた禁止語)。
  - 合格の割合を出し、決めた割合(8割)を下回ったら失敗。
- `.github/workflows/evals.yml`: AI への指示(`_shared/reflect.ts`、`_shared/ai.ts`)や評価用の例を変えた PR でだけ動く。無料枠の回数の上限にかからないよう、例は少なく、間を空けて呼ぶ。
- 本人が下書きを大きく直した例は、本人の了解を得て、言い換えた形で評価用の例に足していく(運用。この plan では仕組みまで)。

### PR #7 のレビューの Nit(3件)
- 「やることに戻す」「いつかに」が失敗したら一言出す。
- 一日の一言の下書きを、日付が変わったら捨てる。
- 「ほかに終えたこと」の完了時刻のずれは、許容として plan/007 に記録済み。完了時刻の列は、必要になってから。

## あなたにお願いする準備
1. Google AI Studio で Gemini の API キーを作る(このアプリと同じ Google アカウントで)。あわせて、無料枠の今の規約(データの使われ方、回数の上限)を確認する。
2. その API キーを、Supabase の Edge Functions の Secrets(`GEMINI_API_KEY`)と、GitHub の Secrets(`GEMINI_API_KEY`、評価用)に登録する。使うモデル名(AI Studio で選べる Flash 系の現行モデル)を、Supabase の Secrets の `GEMINI_MODEL` と GitHub の Variables の `GEMINI_MODEL` に登録する。

## やらない
一日の一言を話して整えること(同じ仕組みで、使ってみてから)。AI 仕分け(R24)。下書きの保存(残すと決めたものだけを保存する)。

## リスク
- **AI が決まりを破る(評価する、付け足す)**: 評価用の例と決まった検査で確かめる。画面では下書きとして出し、本人が直して選ぶ。
- **無料枠の上限**: 1人で週に数回の使い方なら届かない見込み。評価は PR のときだけ、少ない例で回す。届いたら「いまは整えられなかった」と出す。
- **モデル名や API の変化**: モデル名は Secrets にして、コードを変えずに差し替えられるようにする。窓口を1か所にまとめる。
- **評価の検査が粗い**: 決まった言葉の検査は、すり抜けがありうる。まずは粗くても回る仕組みを作り、本番で見つかった例を足して育てる(記事の「インシデントから eval を足す」)。

## 計画からのずれ
- 評価(`npm run eval:reflect`)は、この作業環境では回せていない(Gemini の API キーがなく、外部の API に出られないため)。評価の仕組みが読み込めて動き出すことだけを確かめた。実際の評価は CI(`evals.yml`)で回す。
- 「整える」のほかに「そのまま残す」を置いた(AI を使わずに、話した文章を「この週のこと」に書き足す。AI が使えないときの逃げ道にもなる)。
- 画面側の型(`Reflection`)は、サーバー側の `_shared/reflect.ts` から型だけを読み込んで共有した(形を1か所で決めるため)。
- AI の窓口は `generateJson(prompt, schema)` ではなく `generateJson(config, req)` にし、API キーとモデル名は呼ぶ側(サーバー側の関数、評価)から渡す形にした。窓口を Deno と Node の両方で動かし、本番と評価で同じ窓口を使うため(PR #8 のレビューの Nit)。
- PR #8 のレビューで直したこと: 「残す」の途中で失敗したときに押し直すと、成功した分まで重複していた(Important)。済んだものを覚え、残りだけを送るようにした。AI の返事を待つ上限(30秒)を付けた。評価はキーがないとき、失敗ではなく「回っていない」とはっきり出して飛ばすようにした。
