データの土台(plan/003)ができたので、実際にデータを読み書きする最初の機能を作る。
週の計画の画面はまだないため、最初は「思いついたら放り込む → 今やることを選ぶ → やったかを記録する」という、今ここ(P7)だけで完結する小さな流れを作る。これだけでも日々使い始められ、PC とスマホの間での同期(N3)も確かめられる。

## スコープ
やる:
- ログインしていなければ、ログインの画面だけを出す。
- 放り込む(R1、R3): 画面下に常に1行の入力欄。音声は OS の音声入力を使う(R2)。入れた項目は未分類のまま Inbox に入る。
- 今の画面(R13): 今のブロック名と、今のブロックに置いた項目を大きく表示する。
- Inbox(R13): 折りたたみ。開くと一覧が出て、各項目に「今やる」ボタン。押すと今のブロックに置かれる(R14a)。
- 記録(R14): 今のブロックの項目に、やった、一部、やらなかったを付けられる。今のブロックから外して Inbox に戻すこともできる。
- 初回の利用時に、端末のタイムゾーンで設定(settings)を作る。

やらない(後の plan に回す): 週の計画の画面、今日の残りのブロックの表示、4象限と領域の仕分け、AI 仕分け、哲学者の言葉、PWA 化、Google ToDo の同期。
plan/002 の診断表示は、plan/002 を閉じるまで画面の一番下に小さく残す。

- 自動化(GitHub Actions からマイグレーションを適用する)は、Supabase の秘密の鍵を GitHub に登録する必要があるため、後の plan で検討する。

## 作業の順序
1. `src/domain/slot.ts`: `currentSlot(now, timeZone, blocks)` が `{ weekStart: 'YYYY-MM-DD', day: 0〜6(0 = 月曜), blockId }` を返す。ブロックの外の時間帯は `null`。既存の `weekRange`(`src/domain/week.ts`)、`currentBlock`(`src/domain/blocks.ts`)、`zonedParts`(`src/domain/time.ts`)を使う。テスト3件(平日の午前、日曜の夜、夜中)。
2. `src/data/settings.ts` と `src/data/items.ts`: Supabase の型付きクライアント(`src/data/supabase.ts`)を使う。エラーは画面で扱える形にして返す。
3. 画面: スマホの縦長の画面を基準に作る。文言は CLAUDE.md の規約に従う(命令形にしない、評価色を使わない)。
   - 今のブロックに何もないときは「今は余白の時間です」と肯定的に表示する(P2)。
   - ブロックの外の時間(0〜5時)は「静かな時間です」と表示し、「今やる」は出さない。
4. `npm run lint`、`npm test`、`npm run build`、`npm run test:db` を通し、push して GitHub Pages に配信する。
5. あなたに動作確認をしてもらい、結果を記録する。

## リスク
- **クラウドのテーブルの適用漏れ**: SQL を実行していないと、画面がエラーになる。エラー時は「データの準備ができていません」とわかる表示にする。
- **曜日の数え方のずれ**: JavaScript は日曜 = 0、このアプリは月曜 = 0。変換を `slot.ts` の1か所に閉じ込め、テストで押さえる。
- **画面の確認が手動になる**: Playwright はまだ入れていない(軽さ優先)。ロジックは単体テストで押さえ、画面はあなたの確認に頼る。

## 選ばなかった案
- 週の計画の画面から作る: 使い始めるまでに作るものが多い。「今」から作れば、すぐに日々使える。
- 画面ごとにページを分ける(ルーター): 今は画面が1つで足りる。
- マイグレーションを GitHub Actions で自動適用する: 秘密の鍵の登録が増える。今は1回の手作業で済ませる。
