- plan/016 のあとに出す。spec の変更 9 は plan/016 に書いた内容と同じ

## Context
- 画面の文字が細く薄い。本文の書体を細い 300 で使い、見出しの字間を広く取り(0.18em)、補足を 12〜13px の薄墨にしているため。Windows では特に細く見える(スクリーンショット)。
- やることに領域(仕事、学校など)と「大切なこと / 急ぐこと」を、1件ずつ手で付ける必要がある。spec R24〜R27 で「AI 仕分け」として後回しにしていたもの。

## 変更
### データ
- マイグレーション: `items` に列を足す。`area_source`(`'ai' | 'user'`)、`quadrant_source`(同じ)、`ai_reason`(短い理由)、`ai_tried_at`(見立てを試みた時刻。何度も AI を呼ばないため)。権限はテーブル単位で付いているので変えない。pgTAP で列と既定値を確かめる。`npm run gen:types`。

### サーバー
- `supabase/functions/_shared/classify.ts`(新規、純粋な関数): AI への指示、返す形(各項目の `area`、`important`、`urgent`、`reason`)、応答の検査(領域は5つのどれか、理由は 40 文字以内、命令形や評価の言葉を含まない)。今日の日付と締め切りも渡し、「急ぐこと」は締め切りから判断させる。
- `supabase/functions/classify/index.ts`(新規): ログインした本人の、まだ見立てを試みていない未仕分けの項目を最大 30件まとめて1回で AI に送る(無料枠を節約)。結果は、その時点でまだ本人が付けていない項目にだけ書く(本人が先に付けたものは上書きしない)。`ai_tried_at` を付ける。呼び直しと控えのモデルは `_shared/ai.ts` を使う。文面はログに出さない。
- 呼ぶ時: 同期のあと(`useAutoSync`)と、放り込んだあと。まだ見立てのない項目があるときだけ。

### 画面
- `ItemMeta.tsx`: AI の見立ては、下線を点線にして薄く示し、「見立て」と小さく添える。理由は見立ての横に小さく出す。どれかを押したら、本人の判断(`source = 'user'`)になる。
- やることの一覧(`InboxList.tsx`)に、領域を小さく添える(見立てなら薄く)。開かなくても付いているとわかるように。

### 評価(N7)
- `evals/classify/cases.json`(15件ほど: 仕事、学校の課題、買い物、運動、新規事業のアイデア、締め切りが近いもの・遠いもの・ないもの)。領域の一致率 8 割以上、決まり(理由に命令形や評価がない、急ぐことが締め切りと矛盾しない)を破った例 0。
- `evals/run-classify.ts`、`npm run eval:classify`。`evals.yml` の対象に `_shared/classify.ts` と `evals/classify/**` を足す。無料枠の上限に気をつけ、例は1回の呼び出しにまとめる。

### テスト
- `_shared/classify.test.ts`: 指示の組み立て、応答の検査(領域の外の値、長すぎる理由、命令形を弾く)。
- 書き込みの条件(本人が付けたものを上書きしない)は、関数の中の純粋な判定にして Vitest で確かめる。

## やらない
一文を複数の項目に分けること(R24 の残り)。見立てを止める設定(R27)。週の画面での見立ての表示の作り込み。

## リスク
- **見立てに引っ張られる(C9)**: 「大切なこと」を AI が決めるのは、本人の価値観に踏み込む。薄く示し、理由を添え、本人がすぐ直せるようにする。本人が直した例は evals の題材にする。
- **無料枠の上限**: まとめて1回で送り、一度試みた項目は二度送らない。混み合って失敗したら、次の同期で試す。
- **送る内容(C14)**: やることの文面が Gemini に送られる。プロダクトオーナーが受け入れ済み。
- **太さを変えると見た目の印象が変わる**: 手帳らしさが薄れたと感じたら、500 ではなく 400 にとどめ、手書きの書体はそのまま使う。

## 計画からのずれ
- 評価は、話して省みるの評価(`evals.yml`)と分けて `evals-classify.yml` にした。片方だけ変えた PR で、もう片方の評価まで回して無料枠を使わないため。`evals.yml` の対象も `evals/**` から `evals/reflect/**` と `evals/run-reflect.ts` に絞った。
- 本人の操作は、触れたほう(領域か象限)だけを本人の判断にする形にした(`classifyItem` の引数を、領域か象限のどちらか一方に)。見立ての領域を押すと「そのとおり」と本人の判断になり、本人が付けた領域を押すと外れる。
- 領域と象限の定義は、関数がリポジトリの `src` を読めないため `_shared/classify.ts` にも置き、一致をテストで確かめた。
- Deno の型チェックで、以前からある `_shared/crypto.ts` に2件の型の誤りが出た(新しい Deno の型定義との差)。本番の配信は動いているので、この PR では直していない。
- 再試行できない失敗(設定の誤りなど)や、返事の形が違うときも、その回の項目に `ai_tried_at` を付ける。同じ項目で何度も AI を呼ばないためで、本人は手で仕分けられる。設定の誤りで一度に見立てが付かなくなったときは、`ai_tried_at` を空に戻せば、次の同期で試し直す(PR #14 のレビューの Nit)。
- PR #10〜#14 のレビューの Nit のうち、小さなものをこの PR で直した: 見立ての説明を「違えば、押して直せる。」に(R23)、やることを閉じたら「ほかに N 件」を畳み直す、言葉の巡りの型を厳しく、出典が「句」だけだった俳句に句集や年を添え、出典を確かめにくい良寛の句を外した(夜の束は 33 件で、30 日分を満たす)、spec の R13 と R24〜R26 の元の文に取り消し線と参照を付けた。
- プロダクトオーナーの指摘で、押せるところでポインターが手の形にならない件もこの PR で直した(`src/index.css`。Tailwind v4 はボタンのカーソルを矢印のままにするため)。
