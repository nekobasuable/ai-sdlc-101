# plan/012-mic-and-resilience: マイクのボタンと、AI の混雑への強さ

- 元: プロダクトオーナーの要望(マイクのボタン)と、本番の「いまは整えられなかった」(関数のログ: Gemini: 503)。spec の変更 6(下記)。PR #8 のレビューの Nit 4件
- 状態: 承認済み(承認者: リポジトリオーナー、2026-11-24)

## Context
PC で「話して省みる」を使おうとして、音声入力のやり方がわかりにくかった。マイクのボタンがほしい。
また、本番で「整える」が「いまは整えられなかった」になった。関数のログは「Gemini: 503」(混雑)。試験的なモデルの可能性が高く、プロダクトオーナーには正式版の Flash 系に変えてもらうが、アプリ側でも混雑に強くする。

## spec の変更 6(この plan の承認で受理とする)
- R2 を改める: 音声入力は、OS の音声入力に加えて、「話して省みる」と「ふと浮かんだことを」(放り込む欄)にマイクのボタンを置く。ブラウザの音声認識の仕組みを使い、使えないブラウザではボタンを出さない(OS の音声入力はそのまま使える)。
- C15: ブラウザの音声認識(Chrome など)は、話した音声を提供元のサーバーに送って文字にすることがある。C14 と同じく、プロダクトオーナーが受け入れたリスクとする。
- R42 を補う: AI が混雑しているときは、間を空けて呼び直し、それでもだめなら控えのモデルに切り替える。混雑で整えられなかったときは、そうとわかる一言を出す。

## 変更
### マイクのボタン
- `src/ui/useSpeech.ts`(新規): ブラウザの音声認識(`SpeechRecognition` / `webkitSpeechRecognition`)を包む。日本語(`ja-JP`)、話している間は文字を流し込み、止めると確定する。使えるかどうかを返す。
- `src/ui/MicButton.tsx`(新規): スキルに従い、箱にしない。マイクの線画だけ。聞き取り中は、線が少しだけ濃くなり「聞いています」と添える(押せる範囲は 44px、`aria-pressed`)。
- 置く場所: 「話して省みる」の欄の横、放り込む欄(`Capture`)の入力の横。話した文字は、今ある文字の後ろに足す。
- 純粋な部分(聞き取った文字の足し方: 確定した部分と途中の部分をどうつなぐか)を `src/domain/speech-text.ts` にして、テストする。

### AI の混雑への強さ
- `_shared/ai.ts`: 本番の呼び直しを2回に。`generateJson` に控えのモデル(任意)を渡せるようにし、本命が混雑で失敗したら控えで1回呼ぶ。
- `reflect` 関数: 控えのモデルを Secrets の `GEMINI_FALLBACK_MODEL` から読む(なければ控えなし)。混雑で失敗したときは「いまは混み合っていて、整えられなかった。少しおくと、また整えられる。」を返す。設定(キーやモデル名)が足りないときも、ログに残す(内容は出さない)。
- 評価(`evals/run-reflect.ts`)にも控えのモデルを渡せるようにする(GitHub の Variables の `GEMINI_FALLBACK_MODEL`、任意)。

### PR #8 のレビューの Nit(4件)
- 「話して省みる」の欄に 4000 文字の上限を付け、残りの文字数が少なくなったら小さく添える。
- 週を切り替えたら、話して省みるの下書きを捨てる(`key={weekStart}`)。
- 「整える」の回数の制限: 新しい利用者の登録を止めたので、当面は入れない。plan/011 のリスクに記録済み。
- 評価が「回っていない」で合格扱いになる件: AI への指示を変えた PR では、マージの前に Evals の結果(○×の表)を人が見る、を `REVIEW.md` と CLAUDE.md に書く。

## やらない
一日の一言やこの週のことへのマイク(使ってみてから)。話した音声の保存(文字だけを使う)。

## リスク
- **ブラウザの違い**: Safari では音声認識の動きが不安定なことがある。使えないときはボタンを出さず、OS の音声入力に任せる。画面の確認はあなたに頼る(PC の Chrome と、スマホのブラウザ)。
- **マイクの許可**: 初めて押したときに、ブラウザがマイクの許可を聞く。断られたら「マイクが使えない」と一言出す。
- **呼び直しで待ち時間が延びる**: 最悪で 30秒 × 呼び出し回数。待っている間は「整えています…」を出し続ける。

## 証明(Proof)
- `npm run lint`、`npm test`(`speech-text.ts` と、控えのモデルへの切り替えのテストを含む)、`npm run build` が通る。CI、Evals(合格 8 割、呼べなかった例 2 件以下)、AI レビュー(Important 0 件)を通る。
- あなたの確認(マージ後):
  - PC の Chrome で、話して省みると放り込む欄にマイクのボタンがあり、押して話すと文字が入る。
  - モデルを変えたあと、「整える」で下書きが出る。混んでいたときは、混雑とわかる一言が出る。

## 計画からのずれ
- マイクのボタンの動きは、この作業環境ではマイクがなく確かめられていない。聞き取った文字のつなぎ方(`speech-text.ts`)は単体テストで押さえ、ボタンの動きはプロダクトオーナーに PC の Chrome とスマホで確かめてもらう。
- 放り込む欄で、マイクが使えないときの一言は、欄の上に小さく出す(欄の行は狭いため)。
- 本番の呼び直しの間隔の基準は 5 秒(2回目は 10 秒)。テストでは 0 にできるようにした(`backoffMs`)。
- PR #9 のレビューで直したこと: 聞き取りの途中に送ると、送った文字が欄に戻って二重に入りえた(Important)。送る、整える、残す、手で直す、のときに聞き取りを止め、止めたあとに遅れて届く結果は捨てるようにした。エラーのときも聞き取り中の表示を消すようにした。
