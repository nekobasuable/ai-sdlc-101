# plan/007-weekly-plan-and-review: 週の計画と振り返り

- 元: [spec/life-dashboard.md](../spec/life-dashboard.md) の R4、R8〜R13a、R15〜R17a、P1〜P4、P7、懸念 C1、C2、C7。plan/002 の宿題(カレンダーの読み取りのサーバー化)
- 状態: 承認済み(承認者: リポジトリオーナー、2026-11-23)
- 承認後、この内容を `plan/007-weekly-plan-and-review.md` としてコミットしてから実装に入る。

## Context
intent の中心は「週末に次の週をざっくり計画し、終わったら振り返って次に生かす」サイクルだが、まだ「今」の画面しかない。
ここで週の計画と振り返りを作り、plan/006 で作った流れ(plan → 実装 → PR レビュー → マージ)を、初めて最初から最後まで通す。

## 4つの段階に分け、段階ごとに PR を作る
記事の「小さな PR」に合わせ、1つの段階を1つの PR にする。各 PR は CI と AI レビューを通り、あなたがマージする。

| 段階 | 内容 | spec | PR のあとに使えるようになること |
|---|---|---|---|
| A | 週の画面と、ブロックへの配置 | R8、R10、R11、R13a | 週の全体を見て、項目をどのブロックにも置ける |
| B | カレンダーの予定を週に重ねる(サーバー側で読む) | R9 | 予定が週の画面に出る。1時間で切れなくなる |
| C | 仕分け(領域と象限) | R4、R12 | 項目に領域と象限を付けられる。第2象限を先に置くよう促す |
| D | 振り返り | R15、R16、R17、R17a | 週末に、使った時間の概算と、日々の一言を見返せる |

## 段階 A: 週の画面と配置
- 画面の切り替え: 下に「今」と「週」の2つのタブ。既定は「今」(R13)。ルーターは使わず、状態で切り替える。
- 週の画面(R13a): 7日 × 6ブロックの格子。今週と来週を切り替えられる。
  - 過ぎたブロック: やったこと(結果の付いた項目)で埋まっていく。
  - 今のブロック: 強調する。
  - これからのブロック: 置いた項目を淡く、下書きのように表示する。
  - 何も置かれていないブロックは「余白」として見せる(R10)。空欄を「足りない」ように見せない。
- 配置の操作: スマホで扱いやすいよう、ドラッグではなく「ブロックを押す → 候補から選ぶ」にする(dnd-kit は入れない)。置いた項目は、押して外せる。
- 余白の割合が少ないときだけ、やわらかく知らせる(R11): 例「今週は余白が少なめです」。止めはしない。
- 中身の計算(`src/domain/week-grid.ts`、単体テスト必須):
  - 週の格子を作る(各ブロックが過去・今・未来のどれかを判定)
  - 余白の割合(何も置かれていないブロックの割合)

## 段階 B: カレンダーを週に重ねる(plan/002 を閉じる)
- サーバー側の関数 `google-calendar`: 保管してある長期の鍵で短期の鍵を取り、今週(または来週)の予定を返す。`google-tasks` の鍵の処理を `_shared/google-auth.ts` に切り出して共有する。
- 予定は、時刻から該当するブロックに振り分けて、項目とは見た目を分けて表示する(読み取りのみ)。
  - 振り分けは純粋な関数(`src/domain/calendar-blocks.ts`)にしてテストする。複数のブロックにまたがる予定、終日の予定。
- 試作(`SpikePanel`、ブラウザに控えていた短期の鍵)を消す。PR #1 のレビューの宿題。plan/002 を「結論が出た」として閉じる。

## 段階 C: 仕分け
- 項目を押すと、小さな編集の欄が開き、領域(5つ)と象限(4つ)を選べる。どちらも省略できる(R4)。
- 週の配置の候補では、第2象限(重要だが緊急でない)の項目を先頭に出す(R12、P4)。
- 4象限のマトリックス表示(R5)は、この plan では作らない(必要になってから)。

## 段階 D: 振り返り
- 週の画面の上に「振り返り」の入り口。週末でなくても開ける。
- 集計(`src/domain/review.ts`、単体テスト必須): やった(と一部)ブロックの長さを、象限別と領域別に合計する(R15)。
- 表示(R16): 目標値、合否、赤や緑の色を使わない。数字より先に、やったことと日々の一言を日ごとに並べる(C2)。
- 1日の一言(R17a): 「今」の画面の下に、任意で一言を残せる欄。`daily_notes` に保存する。
- 週のメモと持ち越し(R17): 自由記述のメモ(`weekly_reviews`)。やらなかった項目ごとに「来週へ」か「いつか/やらない」を選べる。

## テーブル
新しいテーブルは作らない(`placements`、`daily_notes`、`weekly_reviews`、`items` の `area` と `quadrant` を使う)。

## やらない(後の plan に回す)
ブロックの区切りの設定(R8a)、カレンダーへの書き込み(R9a)、4象限のマトリックス表示(R5)、通知、哲学者の言葉、PWA 化、AI 仕分け。

## リスク
- **「埋める」方向に見えてしまう(C1、P1、P2)**: 格子の空欄は、「足りない」ではなく「余白」に見せる。文言と色は REVIEW.md の Compliance で確かめる。
- **計集の数字が点数に見える(C2)**: 数字を主役にせず、評価色を使わない。
- **画面の確認が手動**: 段階ごとにあなたに触ってもらう。中身の計算は単体テストで押さえる。
- **段階 B の Google API**: カレンダーの権限はすでにもらっているので、再ログインは不要の見込み。

## 証明(Proof)
- 段階ごと: CI(lint、単体テスト、ビルド、DB テスト)と AI レビュー(Important 0 件)を通り、あなたがマージし、本番で動く。
- あなたの確認:
  - A: 来週のブロックに項目を置ける・外せる。過ぎたブロックにやったことが残る。空いたブロックが余白として見える。
  - B: 週の画面に Google カレンダーの予定が出る。1時間以上たっても出る。
  - C: 項目に領域と象限を付けられる。第2象限が候補の先頭に来る。
  - D: 振り返りで、やったことと一言が日ごとに見え、象限別と領域別の時間の概算が出る。持ち越しを選べる。

## 計画からのずれ
- 段階 A: 「外す」は、その項目がほかのブロックにも置いてあれば候補のままにし、どこにもなくなったときだけ Inbox に戻す(同じ項目を複数のブロックに置けるため。たとえば勉強を週に何回か)。Inbox に戻すのは候補(未完了)のときだけで、完了した項目は完了のままにする(PR #2 のレビューの Important)。
- 段階 A: ブロックに置ける候補は、状態が Inbox か候補の項目(完了と「いつか/やらない」は除く)。同じブロックにすでに置いてある項目は候補から外す(PR #2 のレビューの Nit)。
- 段階 A: 今週と来週を切り替えた直後は、読み込みが終わるまで格子を出さない(前の週の内容を重ねないため。PR #2 のレビューの Nit)。


## 改訂: 段階 C、D(承認者: リポジトリオーナー、2026-11-23)
plan/008〜010 で決まったこと(見た目、自動の同期、締め切り)に合わせて、段階 C、D の作り方を改訂した。段階 B は plan/009 で実装済み。

### Context
plan/007 を承認したあと、見た目(手帳)、言葉(省みる、やること)、自動の同期、締め切り、が決まった。段階 C、D の中身はそのままでは合わないので、作り方を改訂する。
spec の要件(R4、R12、R15〜R17a)は変えない。

### 段階 C: 仕分け(1つ目の PR)
- **入り口**: やること、今日までのこと、今やること、の項目の名前を押すと、その下に小さな欄が開く(押せる範囲は 44px)。
- **領域**: 5つの言葉(仕事、スキル強化、学校、プライベート、新規ビジネス)を手書き風の書体で並べ、選んだものに下線。もう一度押すと外れる(R4、省略可)。
- **象限**: 4象限の番号や表は見せず、2つの問いで決める。
  - 「大切なこと」 / 「急ぐこと」 をそれぞれ押して選ぶ。
  - 中身の計算 `src/domain/quadrant.ts`(テスト必須): 2つの答えと象限(1〜4)を行き来する。大切で急がない = 第2象限。
  - 4象限のマトリックス表示(R5)は、引き続き作らない。
- **第2象限を先に(R12、P4)**: 週の「+」の候補では、大切で急がないものを先頭に並べ、言葉で「大切で、急がないこと」と小さく添える。
- **データ**: 項目の領域と象限を書き換える関数。項目の型に領域と象限を含める。Google ToDo には送らない(対応する入れ物がないため。plan/005 のとおり)。

### 段階 D: 省みる(2つ目の PR)
- **入り口**: タブに「省みる」を足す(今 / 週 / 省みる)。今週と先週を切り替えられる。
- **一日の一言(R17a)**: 「今」の右の列(スマホでは今日のこれからの下)に「今日のことを、一言だけ」。下線だけの欄に手書き風の書体で書き、離れると保存する(`daily_notes`)。
- **省みる画面**(スキルに従う。数字より先に、やったことと一言を見せる。C2、R16):
  1. 日ごとに: 日付、終えたこと・途中までのこと(ブロックの結果から)、その日の一言(手書き風)。
  2. ブロックに置かずに終えたこと(今日までのことから終えたもの)を、「ほかに終えたこと」として時間なしで並べる(PR #5 のレビューの Nit 3)。
  3. 時間の使い方を文章で(R15): 「大切で急がないことに、およそ6時間。」「学校に、およそ9時間。」のように。終えたブロックは長さのまま、途中までは半分として数える。目標値や合否、色は使わない。
  4. 手放したこと(R17): 結果が「今日は手放した」か、結果のないまま過ぎた項目を並べ、項目ごとに「やることに戻す」か「いつかに」を選べる(「いつかに」は状態を「いつか/やらない」にする)。
  5. 週のメモ(`weekly_reviews`): 下線だけの複数行の欄。離れると保存する。
  6. 引用を1つ(週の場面)。ふくろうは本を読む姿。
- **中身の計算** `src/domain/review.ts`(テスト必須): 週の配置と結果、ブロックの長さ、項目の領域と象限から、象限別と領域別の時間(分)を出す。文章にする関数も(「およそ N 時間」、30分未満は「少し」)。
- **データ**: 一日の一言の読み書き、週のメモの読み書き、ブロックに置かずに終えたことの一覧(その週に完了になり、配置のない項目)。

### PR #5 のレビューの Nit(段階 C の PR に含める)
- 「今日までのこと」を、日付が変わったときにも読み直す(依存に日付を足す)。
- 週の「〆」の振る舞い(完了は出さない、過ぎた日の未完了は出す)を plan/010 に追記。
- ブロックに置かずに終えたものの扱いを、この改訂(段階 D の 2.)で決めた。plan/010 からも参照する。

### テーブル
新しいテーブルは作らない(`items` の `area` と `quadrant`、`daily_notes`、`weekly_reviews` を使う)。権限と RLS は plan/003 のテストで確かめ済み。

### リスク
- **数字が点数に見える(C2)**: 時間は文章で、「およそ」を付け、主役にしない。並べる順番も、やったことと一言のあと。
- **「手放した」を責めるように見える**: 「手放したこと」は、選び直す場所として静かに置く。数を数えない。
- **仕分けが面倒になる(P5)**: 仕分けは任意のまま。開かなければ何も聞かれない。

### 証明(Proof)
- 段階ごと: `npm run lint`、`npm test`(`quadrant.ts`、`review.ts` のテストを含む)、`npm run build`、`npm run test:db` が通る。CI と AI レビュー(Important 0 件)を通る。
- あなたの確認(マージ後):
  - C: 項目の名前を押して、領域と「大切なこと / 急ぐこと」を選べる。週の「+」で、大切で急がないことが先頭に来る。
  - D: 「省みる」で、今週の日ごとに終えたことと一言が見え、時間の使い方が文章で出る。手放したことを「やることに戻す」「いつかに」で選び直せる。週のメモが残る。

### 計画からのずれ(改訂後)
- 段階 C: 仕分けで `updated_at` が進み、同期が Google ToDo に書き込んでいた(PR #6 のレビューの Important)。`items` の `updated_at` を、Google ToDo に関係する変更(題名、締め切り、完了かどうか、削除)のときだけ進めるトリガーに替えた(マイグレーション `20261124040000`)。データベースのテストを3件足した。`planSync` の判断は変えていないので、単体テストは足していない。
- 段階 C: 「今日までのこと」を、日付が変わったときにも読み直すよう、読み込みの依存に日付を足した(PR #5 のレビューの Nit)。
- 段階 D: 結果も一言もない過去の日は「静かな一日」と書いた(空欄を「足りないもの」に見せないため。スキルの余白の決まり)。
- 段階 D: 時間の使い方の下に「終えた時間はそのまま、途中までは半分として数えている」と添えた(数え方が見えないと、数字が点数のように読めるため。C2)。
- 段階 D: 週のメモの見出しは「この週のこと」にした(「メモ」より手帳の言葉に近いため)。
- PR #6 のレビューの Nit: 項目の領域と象限を、決まった値だけの型(`Area`、`Quadrant`)にした。Google に送る内容(`toGoogle`)のそばに、`updated_at` を進める条件と対であることをコメントで書いた。
