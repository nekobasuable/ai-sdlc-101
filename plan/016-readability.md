# plan/016-readability: 文字の読みやすさ

- 元: プロダクトオーナーの指摘(「文字の可読性が低い」「領域を手動で選ぶのが煩わしい」)。仕分けは「AI の見立てを薄く示し、直さなければそのまま採用」を選んだ。spec の変更 9(下記)
- 状態: 承認済み(承認者: リポジトリオーナー、2026-11-26)
- plan/017(AI の見立て)と同時に承認。こちらを先に出す

## Context
- 画面の文字が細く薄い。本文の書体を細い 300 で使い、見出しの字間を広く取り(0.18em)、補足を 12〜13px の薄墨にしているため。Windows では特に細く見える(スクリーンショット)。
- やることに領域(仕事、学校など)と「大切なこと / 急ぐこと」を、1件ずつ手で付ける必要がある。spec R24〜R27 で「AI 仕分け」として後回しにしていたもの。

## spec の変更 9(この plan と plan/017 の承認で受理とする)
- R46(新): 文字は読みやすさを優先する。本文は 400 の太さ、本文の大きさは 15px 以上、補足は 13px 以上。字間は広げすぎない。
- R24(改): AI は、まだ仕分けていないやることに、領域と「大切なこと / 急ぐこと」の見立てを付ける。一文を複数の項目に分けるのは、今回はやらない。
- R25(改): AI の見立ては、本人が直さなければそのまま使う(週の候補の並びなど)。見立てだとわかるよう、本人が付けたものより薄く示す。本人が触れたら、本人の判断として扱う。
- R26(改): 見立てには、短い理由を添える(押すと見られる)。
- R27(据え置き): AI の見立てを止める設定は、今回は作らない(使ってみてから)。
- C9 の対応を改める: 「確定は本人」から「本人が直せる。直した例を evals の題材に集める」に。プロダクトオーナーが手間の少なさを優先して受け入れた。
- C14 を広げる: やることの文面も、Gemini の無料枠に送る。プロダクトオーナーが受け入れたリスクとする。



## 変更
- `src/index.css`: 本文の太さを 300 → 400 に。
- 見出しの小さな字(「午前のあいだ」「今日のこれから」など、`text-xs tracking-[0.18em] text-ink-3` の 14か所): 13px、字間 0.08em、`ink-2` にそろえる。共通の部品(`src/ui/Label.tsx`)にまとめて、ばらつきをなくす。
- 「今日のこれから」の本文を `ink-2` → `ink`、15px → 16px。予定がないときの一言(「まだ何も決めていない」)は `ink-3` のまま(余白は控えめに、P2)。
- スキル(`.claude/skills/life-dashboard-look/SKILL.md`)の書体と色の節に、太さと最小の大きさを書く。
- 確かめ方: 本文と補足の、紙の色との明暗の差を単体テストで確かめる(`src/domain/contrast.ts`: 4.5:1 以上)。見た目はあなたの目で(Windows の Chrome とスマホ)。

## リスク
- **太さを変えると見た目の印象が変わる**: 手帳らしさが薄れたと感じたら、500 ではなく 400 にとどめ、手書きの書体はそのまま使う。

## 証明(Proof)
- `npm run lint`、`npm test`、`npm run build` が通る。CI と AI レビュー(Important 0 件)を通る。
- あなたの確認(マージ後): Windows の Chrome とスマホで、文字が前より読みやすい。

## 計画からのずれ
- 小さな見出しは、共通の部品(`Label.tsx`)ではなく、Tailwind の `@utility label`(`src/index.css`)にした。見出しは `h1`、`h2`、`p`、`label`、`button` と要素がまちまちで、部品にすると要素を切り替える仕組みが要るため。
- 12px の補足(`text-xs`)は、すべて 13px にした。
- 「余白の一日」「静かな一日」の字間も 0.2em → 0.1em にした。
- 明暗の差のテストで、色の値が `src/index.css` と同じかも確かめようとしたが、テストの環境では CSS が空で読み込まれるため外した。`contrast.ts` のコメントで、両方をそろえるよう示した。
