# plan/009-seamless-sync: Google ToDo とカレンダーを、操作なしで同期する

- 元: プロダクトオーナーの要望(2026-11-23)。spec の変更 3(下記)、plan/007 の段階 B(カレンダーを週に重ねる)、plan/002 の結論
- 状態: 承認済み(承認者: リポジトリオーナー、2026-11-23)
- 承認後、この内容を `plan/009-seamless-sync.md` としてコミットし、spec の変更 3 を spec に書き込んでから実装に入る。

## Context
プロダクトオーナーから「同期をシームレスにしたい。リストや領域を選ばず、ボタンを押さなくても同期したい。ToDo もカレンダーも」という要望があった。
あわせて、plan/002 の本題の結果が出た: 17:39 にログインし、23:07 にカレンダーを読むと鍵が切れていた。ブラウザで受け取るカレンダー用の鍵は約1時間で切れる。サーバーに保管した長期の鍵を使う方式(Google ToDo で使っているもの)に、カレンダーもそろえる。

## spec の変更 3(この plan の承認で受理とする)
- R29 を改める: Google ToDo の**すべてのリスト**を、選ばなくても同期する。リストと領域の結びつきは、任意の上書きとしてだけ残す(画面からは外す)。
- R31 を改める: アプリで作った項目は、Google ToDo の**最初のリスト**(ふつうは「My Tasks」)に作る。
- R34 を改める: 同期は、ボタンを押さなくても、アプリを開いたとき、アプリに戻ってきたとき、開いている間は数分ごとに行う。「今すぐ同期」のボタンはなくす。
- R9 を具体化する: カレンダーの予定は、サーバー側で長期の鍵を使って読み、ボタンを押さなくても「今」と「週」に出る。
- C11(Google ToDo が膨らむ)は、プロダクトオーナーがシームレスさを優先して受け入れたリスクとして記録する。

## 変更
### Google ToDo(すべてのリストを自動で)
- `supabase/functions/google-tasks/index.ts` の同期: 保管してある結びつきではなく、Google から取ったリストの一覧を使う。結びつきが保管されていれば、そのリストの領域だけを上書きに使う。既定のリストは、保管された既定、なければ一覧の最初。
  - 判断の関数 `planSync`(`_shared/sync.ts`)は変えない。渡すリストの一覧の作り方だけを変える。その作り方を `_shared/sync.ts` に純粋な関数(`linksFromLists`)として足し、テストする。
- 画面から「Google ToDo との同期」の設定欄(`SyncSettings`)を外す。

### カレンダー(サーバー側で読む)
- サーバー側の関数 `google-calendar`(新規): 長期の鍵で短期の鍵を取り、指定した週の予定を返す。鍵の処理は `google-tasks` から `_shared/google-auth.ts` に切り出して共有する(リースは同期だけが使う)。
- 予定をブロックに振り分ける純粋な関数(`src/domain/calendar-blocks.ts`、テスト必須): 時刻のある予定は始まりの時刻のブロックへ。終日の予定は、その日の「終日」として別に扱う。
- 表示:
  - 今: 「今日のこれから」の文章に予定を混ぜる(例: 「夕方には、講義(18:00)がある。」)。今のブロックに予定があれば、今やることの下に小さく添える。
  - 週: 日ごとに、置いた項目と同じ並びで、時刻つきで薄墨で出す。終日の予定は日付の横に。
- 試作の部品(`SpikePanel`)と、ブラウザに控えていたカレンダー用の短期の鍵を消す。plan/002 を閉じる。

### 自動で同期する仕組み(画面側)
- `src/data/autosync.ts`(新規): アプリを開いたとき、タブに戻ってきたとき(`visibilitychange`)、開いている間は5分ごとに、ToDo の同期とカレンダーの読み込みを行う。重なりはサーバー側のリースが防ぐ。終わったら画面を読み直す。
- 失敗しても画面は使える。つながりが切れていたら、画面の下の方に一言だけ「Google とのつながりが切れています。ログアウトして、もう一度開くと戻ります。」を出す。

## やらない
画面を閉じている間の同期(締め切りの通知と一緒に、サーバー側の定期実行で作る)。カレンダーへの書き込み(R9a)。

## リスク
- **すべてのリストを同期する(C11)**: 普段使わないリストのタスクも Inbox に入る。プロダクトオーナーが受け入れたリスクとして記録する。完了済みは取り込まないので、未完了のものだけが入る。
- **5分ごとの同期の負荷**: Google の API とサーバーの関数を開いている間だけ呼ぶ。個人の利用なら上限に届かない見込み。画面が裏にあるとき(`document.hidden`)は止める。
- **既定のリストの変化**: 保管された結びつきに既定がなければ一覧の最初を使うので、Google 側でリストの順番が変わると、作る先が変わりうる。
- **サーバー側の関数は手元で動かせない**: 判断は純粋な関数に寄せてテストし、関数は本番で確かめる(これまでと同じ)。

## 証明(Proof)
- `npm run lint`、`npm test`(`linksFromLists`、`calendar-blocks` のテストを含む)、`npm run build`、`npm run test:db` が通る。CI と AI レビュー(Important 0 件)を通る。
- あなたの確認(マージ後):
  - 何も押さずに、Google ToDo のどのリストのタスクも Inbox に入る。
  - Google ToDo で完了にすると、数分以内(またはアプリに戻ったとき)にアプリでも完了になる。
  - アプリで放り込んだものが、Google ToDo の最初のリストに入る。
  - カレンダーの予定が、何も押さずに「今日のこれから」と週に出る。1時間以上たっても、翌日も出る。

## 計画からのずれ
- 週の画面では、カレンダーの予定を、置いた項目とブロックごとに混ぜて並べず、その日の予定として時刻つきでまとめて先に並べた(1日の流れが読み取りやすく、実装も単純なため)。
- `useAutoSync` は `src/data/` ではなく `src/ui/useAutoSync.ts` に置いた(React の仕組みを使うため。CLAUDE.md の構成で、`src/data/` は Supabase とのやり取りだけにしている)。
- サーバー側の関数 `google-tasks` の「リストの一覧」の操作は、画面からは使わなくなったが、関数には残した(害はなく、あとで設定の画面を戻すときに使える)。
